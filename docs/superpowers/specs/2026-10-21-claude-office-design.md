# Claude Office: 프로젝트별 Claude 작업 시각화 (설계)

작성일: 2026-10-21 · 상태: 사용자 승인 대기

## 1. 의도와 이유

사용자는 여러 프로젝트에서 Claude Code를 동시에 돌린다. 지금은 각 터미널을 열어 봐야 Claude가 무슨 일을 하는지 알 수 있다. 모니터 한쪽에 브라우저 탭을 계속 켜 두고, 3D 회사 사무실 안에서 프로젝트별 아바타가 지금 하는 일에 맞게 움직이는 모습으로 한눈에 파악하고 싶다.

성공 기준: 탭을 흘끗 보면 (1) 어느 프로젝트의 Claude가 켜져 있고, (2) 지금 뭘 하고 있으며, (3) 사용자의 승인·답을 기다리는지 알 수 있다.

## 2. 확정된 요구사항 (사용자가 직접 정한 것)

- 지정한 프로젝트 수만큼 아바타가 있다 (프로젝트당 1명).
- 배경은 회사. 아바타가 자유롭게 돌아다니며 작업 모습에 따라 다르게 보인다.
- 시점은 **3D 아이소메트릭 사무실** (카메라 회전·확대 가능). 목업: `/tmp/claude-1000/-home-hyeanjae/26bf951f-1186-4ade-87d4-6068a101d17f/scratchpad/avatar-office/.superpowers/brainstorm/766573-1792560544/content/office-style-v4.html` 의 C안.
- 말풍선에는 분류명이 아니라 **실제 작업 내용을 짧은 한 줄**로 적는다. 예: "학습에 필요한 데이터 다운 중".
- 모니터 한쪽에 **브라우저 탭으로 상시 켜 둔다.**
- Claude가 꺼져 있으면 **휴게실에서 자고 있다.** 켜져 있지만 작업이 없으면 **휴게실이 아닌 다른 공간에서 쉰다.**

## 3. 목업에서 사용자가 본 것 (유지)

- 방: 자료실, 작업실, 서버실, 회의실, 휴게실. 아바타 위에 말풍선과 프로젝트 이름표.
- 상태 색: 파일 읽는 중(파랑) / 코드 쓰는 중(청록) / 명령 실행 중(보라) / 승인 기다리는 중(주황) / 쉬는 중(회색).
- 상태별 위치: 읽기→자료실, 코딩→작업실 책상, 명령 실행→서버실, 승인 대기→회의실.
- 일러스트 톤: 밝은 사무실, 둥근 캐릭터, 프로젝트마다 다른 셔츠 색. 사용자가 처음 목업을 "허접하다"고 해서 다듬은 상태이므로 실제 화면도 이 수준 이상의 완성도를 유지한다.

## 4. 목표 / 비목표 / 피해야 할 것

**목표**
- 여러 프로젝트의 Claude 상태를 실시간(몇 초 이내)으로 한 화면에 표시.
- 상태 변화에 따라 아바타가 방 사이를 걸어서 이동.
- 설정 파일 하나로 프로젝트 추가/삭제.

**비목표**
- Claude를 이 화면에서 조작하거나 승인하는 기능은 만들지 않는다 (보기 전용).
- 외부 공개/팀 공유, 계정·로그인은 없다. 사용자 본인 PC에서만 쓴다.
- 작업 이력 저장·통계는 이번 범위 밖.

**피해야 할 것 (실패로 보는 경우)**
- 화면은 예쁜데 상태가 실제와 안 맞거나 한참 늦다.
- Claude Code 작업 속도를 hook이 눈에 띄게 늦춘다.
- 민감한 내용(키, 비밀번호 등)이 말풍선 요약에 그대로 노출된다.
- 탭을 오래 켜 두면 느려지거나 멈춘다.

## 5. 사용자가 정하지 않았고 내가 정한 것 (검토 필요)

1. **상태 수집:** 각 프로젝트의 Claude Code hook(도구 사용 전후, 승인 요청, 응답 종료, 세션 시작/종료)이 내 PC의 로컬 서버로 신호를 보낸다. 실제로 승인 대기와 세션 종료를 구분해서 받을 수 있는지는 구현 초기에 먼저 확인한다.
2. **말풍선 요약:** 도구 호출 내용(명령, 파일 경로 등)을 작은 모델로 한국어 20자 안팎 한 줄로 요약한다. 사용자의 Claude 구독으로 실행하고 API 키는 쓰지 않는다. 요약이 늦거나 실패하면 "파일 읽는 중" 같은 기본 문구로 대체한다. 요약 전에 비밀값으로 보이는 문자열은 가린다.
3. **구조:** 로컬 서버(hook 수신 + 요약 + 웹소켓으로 브라우저에 전달) 하나와 웹 페이지 하나. 별도 설치 없이 주소만 열면 된다.
4. **프로젝트 지정:** 설정 파일에 폴더 경로와 아바타 이름(및 선택적으로 셔츠 색)을 적는다.
5. **상태 → 방 매핑:** 목업 기준. 쉬는 상태는 "할 일 없음 = 복도/창가", "꺼짐 = 휴게실 소파에서 수면".
6. **3D 구현:** 브라우저 3D 라이브러리(Three.js 계열)로 아이소메트릭 카메라, 캐릭터는 단순한 둥근 모델과 걷기·타이핑·수면 애니메이션.
7. **위치:** `/home/hyeanjae/projects/claude-office/`. 서버는 WSL에서 돌고, 브라우저는 Windows에서 연다 (localhost 접근 확인 필요).

## 6. 제약

- 환경: WSL2(Linux) + Windows 브라우저. 사용자는 한국어.
- 프로젝트가 여러 폴더에 흩어져 있고, 같은 폴더(홈)에서 여러 세션이 열리기도 한다. 세션을 프로젝트에 매핑하는 기준은 작업 폴더로 한다.
- 모든 날짜·시간 표기는 KST.
- 기존 Claude Code 전역 설정(hook)을 건드리므로, 기존 hook은 유지하고 추가만 한다. 변경 전에 사용자에게 확인한다.

## 7. 빌더에게 맡기는 것

- 3D 모델 구성, 애니메이션 세부, 카메라 조작 방식.
- 방 배치의 세부 좌표와 걸어가는 경로 계산.
- 서버 언어와 라이브러리 선택(위 구조를 지키는 범위에서).
- 요약에 쓸 구체적인 모델과 호출 방식.
- 말풍선 문구의 세부 형식(길이, 말투).

## 7-0. 사용자 추가 답변

- 동시에 보는 프로젝트는 **5개**. 아바타 5명 기준으로 사무실 크기와 방 배치를 잡는다.
- 사용자가 Claude Code 안에서 직접 부를 수 있어야 한다: `/office` 슬래시 명령으로 서버 시작과 브라우저 탭 열기, 프로젝트 추가(`/office add`)는 내 제안이며 구현 때 확인.
- 작업 종류(상태): 읽기·검색·웹 조회 / 코드 작성 / 명령 실행 / 승인·답변 대기 / 할 일 없음 / 꺼짐. (§3 매핑 표)

## 7-2. 팀 구성 (사용자 아이디어로 추가)

- 프로젝트 하나 = 팀 하나. 5개 팀이 한 회사를 이룬다.
- **팀장 = 프로젝트의 메인 Claude.** 앞서 정한 아바타·말풍선·이름표·꺼짐(휴게실 수면)·쉬는 중 동작은 팀장에게 적용된다.
- **팀원 = 하위 에이전트.** 팀장이 하위 에이전트를 띄우면 그 팀 구역에 팀원이 **나타나서 일하고, 끝나면 퇴근해서 사라진다.** 항상 앉아 있는 고정 팀원은 없다. 팀원 말풍선에는 맡은 일이 한 줄로 표시되고, 이름표는 에이전트 종류를 쓴다.
- **배치(내 추측, 검토 필요):** 팀마다 자기 책상 구역(팀장석 + 팀원이 앉을 자리)을 갖고, 자료실·서버실·회의실·휴게실은 공용이다. 팀장이든 팀원이든 일 종류에 따라 공용 방으로 걸어간다.
- 한 팀에 팀원이 동시에 많이 뜨면 최대 표시 인원(기본 4명, 설정으로 변경)까지만 그리고 나머지는 "+N"으로 표시한다.
- hook이 하위 에이전트의 시작·종료를 구분해 주는지, 어느 팀원의 도구 호출인지 알려 주는지는 구현 첫 단계에서 실제 신호로 확인한다. 안 되면 팀원은 "하위 에이전트 N명 작업 중"으로 단순화한다.

## 7-3. 완료·승인 알림 (사용자가 1번만 선택)

- 화면 안 연출만 만든다. 탭 제목 배지, "방금 끝난 일" 목록, 소리, 데스크톱 알림, 폰 푸시는 이번 범위 밖(나중에 추가 가능).
- **완료:** 팀장이 `celebrateAfterSeconds`(기본 30초) 이상 일한 뒤 끝나면, 팔을 들어 올리고 말풍선이 "완료!"로 바뀌며 책상 주위에 초록 링이 약 4초 반짝인 뒤 쉬는 상태로 돌아간다. 짧은 질답에는 연출하지 않는다.
- **승인 대기:** 아바타 머리 위에 주황 느낌표가 계속 깜빡인다(승인이 끝나면 사라짐).

## 7-1. 검토에서 나온 질문에 대한 결정 (내가 정한 것, 검토 필요)

1. **hook 설치 위치:** 전역 `~/.claude/settings.json`에 추가만 한다(기존 hook 유지). 신호에는 세션의 작업 폴더가 들어가고, 서버가 설정 파일의 프로젝트 폴더와 **폴더 경로 접두사로 매칭**한다. 지정하지 않은 폴더(홈 포함)의 신호는 버린다. 같은 프로젝트에서 세션이 여러 개면 아바타는 1명이고 가장 최근에 활동한 세션을 표시한다.
2. **hook 동작:** 보내고 잊는 방식(fire-and-forget), 타임아웃 1초 이내, 서버가 꺼져 있으면 조용히 건너뛴다. 도구 호출을 절대 막지 않는다. 서버는 systemd 사용자 서비스로 WSL 시작 시 자동 실행한다.
3. **꺼짐 vs 쉬는 중:** 세션 종료 신호를 받으면 "꺼짐"(수면). 종료 신호 없이 오래 조용한 경우를 위해, 진행 중이던 도구가 끝난 뒤 일정 시간(기본 10분) 신호가 없으면 "꺼짐 추정"으로 본다. 그 전에는 "쉬는 중"(작업 없음, 휴게실이 아닌 복도/창가). 임계값은 설정으로 뺀다.
4. **요약 방식:** 서버가 작은 모델을 헤드리스로 호출한다(구독 사용). 이 호출이 hook을 다시 일으키지 않도록 요약 호출에는 hook을 끄는 환경변수/설정을 쓰고, 이를 구현 초기에 검증한다. 요약이 불가능하거나 실패하면 규칙 기반 문구("파일 읽는 중" 등)로 대체한다. 따라서 요약은 선택 계층이고, 규칙 기반 문구가 기본 동작이다.
5. **민감정보:** 요약기에 넘기기 전에 서버에서 마스킹한다(토큰·키·비밀번호 패턴, `.env`·키 파일 경로는 내용 없이 "설정 파일"로 표기). 말풍선과 로그에도 마스킹된 문장만 쓴다.
6. **도구 → 방:** 읽기·검색 계열→자료실, 편집·쓰기→작업실, 셸 실행→서버실, 웹 검색/가져오기→자료실, 하위 에이전트·MCP→작업실, 승인 대기→회의실. 한 세션에서 여러 도구가 병렬이면 가장 최근 신호를 따른다. 구현 첫 단계에서 실제 hook 신호 내용을 확인해 사용자에게 보여 준다.
7. **3D 규모:** 목업 C의 방 배치와 색 분위기는 유지하되 정확한 복제는 아니다. 탭이 숨겨지면 렌더링을 멈추고, 보일 때만 저프레임으로 그린다. 목업 사본: `/home/hyeanjae/projects/claude-office/docs/mockups/office-style-v4.html` (생성기 `make_mockup.py`).
8. **첫 실행:** 설정을 직접 바꾸지 않는다. hook 설정 조각과 설치 스크립트를 만들어 사용자가 확인한 뒤 적용한다. 서버는 localhost에만 바인딩하고, WSL 네트워크 방식(미러드/NAT)에서 Windows 브라우저로 접속되는지 구현 초기에 확인한다. 포트는 빌더가 고른다.

## 8. 열린 위험

- hook이 "승인 기다리는 중"을 신뢰성 있게 알려 주는지 불확실. 안 되면 해당 상태를 "응답 대기"로 단순화하고 사용자에게 알린다.
- 요약용 모델 호출 비용/지연. 구독 한도를 쓰므로 호출 빈도를 제한(예: 같은 상태가 이어지면 재요약 안 함)해야 한다.
